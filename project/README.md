# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект демонстрирует применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и (по возможности) воспроизводимость.

- **Название проекта:** `Анализ тональности отзывов клиентов`
- **Автор:** `Сахарова Мария Алексеевна`
- **Группа:** `БСБО-51-24`

- **Краткое описание (2-4 предложения):**  
  >`ML-сервис, который автоматически определяет тональность текстового отзыва пользователя (positive / negative). Сервис может использоваться для автоматического анализа обратной связи клиентов, мониторинга качества сервиса или продукта и приоритизации негативных обращений.Используются данные из открытого даатсета Amazon Reviews.`
  >`Основные метрики: Accuracy, F1-score, Precision / Recall, confusion matrix.`
  >`Модели TF-IDF + Logistic Regression, TF-IDF + NaiveBayes, CatBoost, DistilBERT, а позже анализ и выбор лучшей модели. С подбором гипер параметров.`
  >`Результат - REST API-сервис, который: принимает текст отзыва, возвращает: предсказанный класс тональности, confidence score.`

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `.dockerignore` - файл для Docker, поместила сюда чтобы ничего не ломать.
- `artifacts/`
> - `eda_distribution.png` - результаты работы eda.
> - `README.md` - описание артефактов подробно.
> - `mlflow/` - папка с логами.
> - - `mlflow.db` - база данных логов.
> - `models/` - папка с моделями.
> - - `bert_model\`, `tokenizer\`, `label_encoder.pkl` - файлы лучшей модели.
> - - `confusion_matrix_....png` - confusion матрицы для всех моделей.
> - - `tfidf_vectorizer.pkl` - для некоторых моделей.
- `configs/`
> - `config.py` - файл со всеми путями.
> - `README.md` - описание configs.
- `data/`
> - `README.md` - описание того, что должно быть в data.
> - `processed/`, `raw\` - пустые папки для данных.
- `docker /` - файл для сборки докера.
> - `Dockerfile`
- `notebooks/`
> - `eda.ipynb` - анализ data.
> - `README.md` - с описанием моделей.
> - `experiments/` 
> > - файлы с эксперементами и запусками моделей.
> > - `leaders.ipynb` с выявлением лучшей модели.
- `src/` – основной код проекта.
> - `README.md` - описание структуры и назначения модулей проекта.
> - `api/`
> - - `__main__.py` - точка входа для запуска API сервиса.
> - - `api.py` - реализация FastAPI приложения и endpoints.
> - `data/`
> - - `basic_data_clearing.py` - базовая очистка и нормализация текстовых данных.
> - - `load_data.py` - загрузка и чтение исходного датасета.
> - `features/`
> - - `preprocess_ml.py` - preprocessing текста для ML pipeline.
> - - `split_data.py` - разделение датасета на train/test выборки.
> - - `vectorize_tfidf.py` - TF-IDF векторизация текстов.
> - `models/`
> - - `export_best_model.py` - экспорт и сохранение лучшей обученной модели.
> - - `inference.py` - inference pipeline и предсказания модели.
> - `utils/`
> - - `mlflow_safe.py` - безопасная работа с MLflow tracking.
> - - `mlflow_utils.py` - вспомогательные функции для MLflow.
- `tests/` – тесты (юнит-тесты, простые проверки).
> - `README.md` - описание тестов и способов запуска.
> - `test_api.py` - тестирование FastAPI endpoints.
> - `test_model.py` - тестирование inference и предсказаний модели.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10`
- pip
- venv

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение (опционально, но рекомендуется)
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
python -m pip install --upgrade pip
pip install -r requirements.txt

```

## 4. Как запустить проект

# 4.1 Полная проверка работы на всех данных

```bash
# Если нужно сделать полную проверку всей программы, включая полное обучение на большой выборке, то сначала надо в папке проекта выполнить загрузку данных. Для этого у пользователя должен быть файл с секретами kaggle.

#Все последующие команды выполняются в Terminal Powershel
# Загрузка raw data
python -m src.data.load_data

# Очистка данных
python -m src.data.basic_data_clearing

# Разбивка данных на тестовую и учебную части
python -m src.features.split_data

# Дополнительная обработка для некоторых моделей
python -m src.features.preprocess_ml

# Векторизация для некоторых моделей
python -m src.features.vectorize_tfidf

# После этого в папке data должны появиться папка raw с 3 файлами и processed с 5 файлами

# Чтобы посмотреть анализ загруженных и обработанных файлов надо перейти в папку notebooks и запусть eda.ipynb

```
После выполнения этих команд можно запускать обучение основных моделей. Они находятся в папке /notebooks/experiments
Там же находятся mlruns логи того, как происходило их обучение.

После обучение модели происходит логирование и сравнение её результатов(метрик) с другими ранее запущенными, а также сохранение confusion_matrix для последнего запуска каждой модели. Поскольку в моём случае лучшей моделью является DistilBert именно эта модель сохраняется в artifacts/models для дальнейшего использования в API.

После запуска всех моделей проверяем какая лучшая: notebooks/experiments/leaders.ipynb

После определения лучшей модели в её ноутбук в самый конец добавляем(уже добавлено для DistilBert)

```bash
from src.models.export_best_model import export_artifacts

export_artifacts(
    # Данные заполняем в зависимости от модели. Тут пример заполнения
    model=model,
    label_encoder=label_encoder,
    vectorizer=vectorizer ,
    tokenizer=None
)
```

После этого данные о лучшей модели сохранятся в artifacts/models

```bash
# В корне проекта к консоли
python -m src.models.export_best_model

```

# 4.2 Проверка исключительно работы самого сервиса

Можно посмотреть логи обучения моделей, запустив MLFlow:

```bash
# В корневой папке
mlflow ui --backend-store-uri sqlite:///artifacts/mlflow/mlflow.db
# Должно отобразиться INFO:     Application startup complete. После этого нужно в браузере перейти на http://127.0.0.1:5000, где будут все логи проекта
```

Также можно провести тестирование

```bash
# В корневой папке
python -m pytest
# Должно отобразиться 7 passed. Допустимо наличие warnings, это не влияет на работу
```

Также можно проверить работу модели при помощи API:

```bash
# В корневой папке
uvicorn src.api.api:app
# Должно отобразиться Started server process. После этого можно перейти на сайт http://127.0.0.1:8000/docs и проверить работу API
```

Также можно использовать Docker
```bash
# В корневой папке c запушенным докером
docker build -f docker/Dockerfile -t sentiment-api .

# Ждём пока Building ...s (11/11) FINISHED 

# Запускаем работу сервиса
docker run -p 8000:8000  sentiment_analysis

# Должно отобразиться Application startup complete. После этого можно перейти на сайт http://127.0.0.1:8000/docs и проверить работу API
```
