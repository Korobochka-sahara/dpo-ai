# Отчёт по итоговому проекту по курсу «Инженерия Искусственного Интеллекта»

---

## 1. Паспорт проекта

* **Название проекта:** Анализ тональности отзывов клиентов
* **Автор:** Сахарова Мария Алексеевна
* **Группа:** БСБО-51-24
* **Контакт:** @korobochka_sahara
* **Ссылка на репозиторий:** `https://github.com/Korobochka-sahara/dpo-ai`

Проект представляет собой ML-сервис для автоматического определения тональности текстовых отзывов пользователей. Сервис классифицирует отзывы на positive и negative и может использоваться для анализа обратной связи клиентов, мониторинга качества сервиса или продукта, а также для автоматической приоритизации негативных обращений. В проекте реализован полный ML pipeline: загрузка и обработка данных, обучение и сравнение моделей, логирование экспериментов, экспорт лучшей модели и REST API сервис для inference.

---

## 2. Постановка задачи и контекст

### 2.1 Предметная область и задача

Проект относится к области NLP (Natural Language Processing) и решает задачу бинарной классификации текста — определения тональности пользовательского отзыва.

Потенциальные пользователи:

* компании, анализирующие отзывы клиентов;
* сервисы поддержки пользователей;
* платформы электронной коммерции;
* аналитические системы мониторинга качества.

Основной сценарий использования:
пользователь отправляет текстовый отзыв, а сервис автоматически определяет эмоциональную окраску текста и возвращает вероятность предсказания.

---

### 2.2 Формулировка задачи в терминах ML

Входные данные:

* текст отзыва пользователя.

Выход модели:

* класс тональности (`positive` или `negative`);
* confidence score модели.

Основные требования:

* высокая точность классификации;
* возможность быстрого inference;
* воспроизводимость обучения;
* удобный REST API интерфейс.

---

### 2.3 Метрики качества

Для оценки моделей использовались:

* Accuracy;
* F1-score;
* Precision;
* Recall;
* Confusion Matrix.

Основной метрикой являлся F1-score, так как он позволяет учитывать баланс между precision и recall и особенно полезен при потенциальной несбалансированности классов.

## 3. Данные

### 3.1 Источник данных

Использовался открытый датасет Amazon Reviews:

* https://www.kaggle.com/datasets/bittlingmayer/amazonreviews

Датасет содержит несколько миллионов текстовых отзывов пользователей Amazon и соответствующие метки тональности.

---

### 3.2 Структура данных

Основные данные представлены в виде CSV файлов.

Ключевые поля:

* текст отзыва;
* label sentiment.

---

### 3.3 Предобработка и EDA

В рамках preprocessing выполнялись:

* очистка текста;
* удаление лишних символов;
* нормализация;
* токенизация;
* TF-IDF векторизация;
* разделение train/test выборок.

Для нейросетевых моделей использовался tokenizer DistilBERT.

EDA и анализ данных выполнялись в:

* `notebooks/eda.ipynb`

Основные наблюдения:

* данные достаточно хорошо сбалансированы;
* присутствовали шумовые символы;
* длинные отзывы иногда ухудшали качество baseline моделей.

---

## 4. Модели и подходы

### 4.1 Baseline модели

В качестве baseline были использованы:

* TF-IDF + Logistic Regression;
* TF-IDF + Naive Bayes.

Baseline модели показали хорошую скорость обучения и inference, но уступали по качеству более сложным подходам.

---

### 4.2 Улучшенные модели и эксперименты

Дополнительно были протестированы:

* CatBoost;
* DistilBERT.

Проводились эксперименты:

* с различными preprocessing pipeline;
* с параметрами TF-IDF;
* с настройками batch size и learning rate;
* с различными параметрами обучения CatBoost.

Все эксперименты логировались через MLflow.

Ноутбуки с экспериментами:

* `notebooks/experiments/`
* `notebooks/experiments/leaders.ipynb`

---

### 4.3 Нейросетевые модели

Основной нейросетевой моделью являлся DistilBERT.

Особенности обучения:

* tokenizer HuggingFace;
* fine-tuning предобученной модели;
* обучение на GPU (при наличии);
* использование batch processing.

DistilBERT показал лучшие результаты по качеству среди протестированных моделей.

---

## 5. Экспериментальный протокол и результаты

### 5.1 Протокол экспериментов

Данные разделялись на:

* train;
* test.

Метрики вычислялись на test выборке после полного обучения модели.

Все результаты логировались в MLflow.

---

### 5.2 Сравнение моделей

| Модель              | Особенности         | Accuracy | F1-score | Комментарий                        |
| ------------------- | ------------------- | -------- | -------- | ---------------------------------- |
| Logistic Regression | TF-IDF baseline     | ~0.88    | ~0.88    | Быстрая baseline модель            |
| Naive Bayes         | TF-IDF baseline     | ~0.87    | ~0.87    | Простая интерпретируемая модель    |
| CatBoost            | Градиентный бустинг | ~0.89    | ~0.89    | Хороший баланс скорости и качества |
| DistilBERT          | Transformer model   | ~0.90    | ~0.90    | Лучшая итоговая модель             |

---

### 5.3 Финальная модель

В качестве финальной модели был выбран DistilBERT.

Причины выбора:

* лучшие метрики качества;
* высокая устойчивость к различным типам текстов;
* хорошее качество на сложных примерах.

Trade-off:

* более медленный inference;
* более высокие требования к ресурсам.
